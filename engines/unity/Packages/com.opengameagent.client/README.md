# OpenGameAgent Unity C# client

This package is a thin client for an OpenGameAgent Runtime sidecar or remote server. The Runtime owns the Pi-backed Agent loop; Unity keeps authoritative game state and applies durable actions on its main thread through `IAuthoritativeActionAdapter`.

Configure the Runtime URL, authentication token, JSON request-body limit, separate JSON and attachment response byte limits, request timeout, idle polling interval, authoritative-action execution duration, and finite receipt/reconcile retry-delay schedule in the host project. The package intentionally supplies no guessed operational defaults. `ReadAttachment` returns binary PNG bytes only after checking the reference, declared and received length, SHA-256 content address, RFC 9530 digest, ETag, media type, and privacy headers. Runtime requests do not follow redirects, and non-success attachment responses are constrained by the smaller JSON response budget.

`AuthoritativeActionPump` consumes the Runtime's atomic next delivery: `dispatch` invokes `IAuthoritativeActionAdapter.Execute`, while `reconcile` invokes `Inspect` and never executes the action again. The pump binds its session and actor selector at startup and halts before adapter code if any later delivery disagrees. Each callback receives the stable generated `RuntimeActionRecord`; the pump privately captures the session, actor, operation, claim token, attempt, and claim expiry before invoking game code, so mutating the public record cannot change a later receipt, reconciliation, or conflict read.

Adapter code may begin an authoritative world write only through the short-lived `TryCommit(recheckExpectedAuthority, gameTransaction)` permit. The first synchronous callback rechecks game-owned expected authority; only `true` admits the second callback, which deduplicates the operation, applies the write, and returns application evidence in one game transaction. Neither callback may retain the permit across a frame or await. The permit closes atomically before either callback begins, preventing synchronous re-entry. Inspection completion and authoritative commits are accepted only on Unity's main thread. Stop, expiry, deadline, epoch replacement, rejected authority, or a prior completion closes the corresponding permit. An expired execution fence, incomplete callback, or execution exception enters `Inspect` and reconciliation because a synchronous game transaction may have failed after a partial effect; inspection failure leaves the pump halted and unresolved.

Completion freezes the receipt or reconciliation, including nested result evidence, against the privately captured claim fence. Every retry serializes that same owned evidence; later caller mutation cannot change the outcome, resolution, selector, or payload. Client failures distinguish local pre-dispatch rejection, ambiguous transport, HTTP responses, and successful-response protocol failures. The pump retries only no-response transport failures and HTTP 5xx outcomes according to the host's finite schedule; local serialization/request-limit failures, protocol failures, redirects, and HTTP 4xx responses are never treated as transport ambiguity. Exhausting the schedule leaves the action unresolved.

After a 409, the pump reads Runtime authority and requires the exact session, actor, and operation. `pending`, `succeeded`, and `failed` are settled. A returned `claimed` or `uncertain` record with a changed claim fence is inspected and reconciled without executing the action again; if a later authoritative read returns the same unresolved fence, the pump halts instead of cycling indefinitely. A successful receipt with `unknown` outcome or reconciliation with `unknown` resolution also remains unresolved and halts the pump.

`ReadDeferred`, `ResumeDeferred`, and `AbandonDeferred` are C# coroutine wrappers over the same bounded JSON POST transport. Each invocation performs one explicit request without polling, coalescing, or automatic retry. Stopping a coroutine or observing a transport failure does not prove whether the server committed a command; call `ReadDeferred` before deciding whether to issue another explicit command. If the host also consumes the Runtime's canonical event stream through a separate process or SDK, reconcile that stream in the host as a second source of durable evidence; this Unity package does not currently expose the event stream.

The repository's local editor gate targets Unity 6 (`6000.x`). Compatibility with older Unity versions is established only by a consumer that requires and tests that version.

`ListApprovals` and `DecideApproval` are single-request coroutine wrappers over the bounded JSON transport. Their generated
DTOs expose the optional host-projected JSON as `Request.Presentation`. Unity may interpret that value only as game-owned
review data and must submit decisions with the same approval ID, revision, and request fingerprint. The presentation itself
grants no authority and must not be cached as a second approval record.
